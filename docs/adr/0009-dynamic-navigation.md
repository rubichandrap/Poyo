# Dynamic navigation: explicit-only client navigation with Next.js-parity traversal

**Status**: accepted; decision 2's cold-entry clause superseded by ADR 0019; decisions 6 and 7 amended and decision 8 added (2026-11-18). Decided with the maintainer in a grilling session (2026-09-23); the capability's glossary name is **Dynamic navigation** — Pwo's own name was left provisional (its ADR recorded a near-tie between "hybrid/client/soft navigation"), and Poyo does not inherit that indecision.

Every route transition in Poyo is a full document load, which discards the React shell: providers, the react-query cache, and any long-lived client session die on navigation. We add **dynamic navigation**: `useRouter()` for programmatic navigation and `<Link>` for declarative links swap the active page component below the shell while the document stays loaded. Unlike Pwo's implementation — the reference for this feature — Poyo ships **no global interception**: there is no Navigation API `event.intercept`, no document-level click listener, no eligibility net over arbitrary anchors. The only navigation drivers are the explicit API and `Link`'s own click handler.

**Decisions**:

1. **Explicit-only drivers** (maintainer decision): `router.push/replace` and `<Link>` share one navigation path; nothing else navigates without a document load. A plain `<a>` in app code is a document load, by design — the boundary is visible in the code that invokes it.
2. **Traversal is Next.js parity** (maintainer decision): browser Back/Forward between entries of the loaded document fetch a descriptor and swap the page (`popstate` path only); an entry of another document is the browser's own document load (ADR 0019, which superseded the original cold-entry clause; archived in `archive/0009-superseded.md`). With traversal, scroll restoration comes too: history entries store their scroll position (the `pwo-hybrid` state pattern), restored on the way back.
3. **The wire contract is access-enforced from day one.** A descriptor request (`X-Poyo-Navigation: 1`) is answered by `PageResult` with `{ name, seo, pageData }` as JSON and `Vary: X-Poyo-Navigation`; `RouteAccessFilter` runs before the result executes, so a `protected` route's descriptor challenges anonymous callers — a 401/redirect, never a leaked payload. Pwo deferred server-side enforcement with its descriptor already shipping; Poyo closes that gap at birth.
4. **The registry gains `"dynamic": false`** (per-route opt-out, default `true`), validated at boot by `RoutePolicy` and by the CLI on every read. The name follows the glossary, not Pwo's `"hybrid"`. The server honors it (`PageResult` answers the document when opted out) — it is a server-side enforcement point, not a client convention.
5. **The registry does NOT gain `head` additions.** Poyo's client is a single Vite bundle — every page's CSS ships in the one entry stylesheet — so per-route head additions have no consumer. The field is additive later without breaking the wire contract. (Pwo needs it for page-scoped CSS in consuming apps; Poyo has no consuming-app model.)
6. **Popstate guards from review**: a hash-only change never enters the machinery (the browser owns anchor scrolling), and a last-write-wins token drops superseded traversals. A navigation also supersedes the one before it at the transport: the descriptor request is aborted (`AbortController`), so a response nobody will read does not stay open, and `router.destroy()` bumps the token and aborts the request so nothing the router was waiting for commits, writes history or scrolls afterwards. (The token-only wording, which left the request open, is archived in `archive/0009-superseded.md`.)
7. **Fallback floor unchanged, through the requested history operation**: any failure — non-2xx, non-descriptor body, unknown page name, a page module that cannot load, apply error — ends in a document load for the same URL, via the history operation the caller asked for: `push` falls back push-equivalent (`location.assign`) and `replace` falls back replace-equivalent (`location.replace`), as every traversal fallback already did. A failed `replace` therefore never grows the stack, and a failed `push` never collapses it. The opt-out (`dynamic: false`) reaches the same floor without the request: the registry's flag rides on `AppRoute.dynamic` (optional; a hand-built route without one is dynamic), and the router and `Link` hand a non-dynamic route — or a same-origin path the route table does not know — to `location.assign`/`location.replace` directly. A server that still answers a descriptor request with the document (deploy skew) falls back through the same floor. The route's page module loads between descriptor resolution and the store commit, so a chunk that no longer exists — a tab left open across a deploy — takes that floor before anything is committed, and a page already in memory renders without a Suspense flash. (The earlier "the client never learns the flag" wording is archived in `archive/0009-superseded.md`.)
8. **The router does no wasted or stale work** (2026-11-18): a superseded descriptor request is aborted, not ignored; `destroy()` cancels in-flight work so nothing commits, writes history or scrolls after it; a `dynamic: false` route or a same-origin path outside the table is a document load without a descriptor request; and `useRouter` returns the same object while the route is unchanged, so a same-route commit that refreshes Page data does not churn a consumer's dependencies.

**API surface** (deliberate divergence from Pwo, following Next.js's split):

```ts
import { Link } from "@rubichandrap/poyo/runtime/link";       // declarative — next/link
import { useRouter, createRouter } from "@rubichandrap/poyo/runtime/router"; // programmatic — next/router
```

One import site per concept, named after the thing it exports. The runtime root re-exports both.

**Considered options**:

- **Pwo-parity global interception** (Navigation API + document-level click eligibility): rejected — the maintainer wants no interception; the machinery it deletes is the largest, riskiest part of Pwo's runtime (guarded clicks, interception loops, traversal bookkeeping in two paths), and its benefit — hijacking plain anchors — is exactly the behavior explicit-only wants to make visible.
- **Document-load traversal** (no popstate handling): rejected by the maintainer — Back after a `push` must not reload the document; Next.js-parity traversal is the expected feel.
- **Full head-additions port**: rejected for v1 — no consumer in Poyo's single-bundle model; additive later.
- **Descriptor request for a non-dynamic route** (the first version's behavior): the client did not learn the flag, so the server answered the document and the unparseable body fell back. Every non-dynamic navigation therefore cost a descriptor request and a second controller run. Reversed 2026-11-18: the flag rides on `AppRoute` and the request is skipped.

**Consequences**: the runtime grows the navigation core (descriptor fetch, parse, route-table lookup, store commit, history writes, scroll restore) with exactly two drivers — roughly half of Pwo's surface; the store/`usePage` contract carries over (the store is what `usePage` reads; `window.SERVER_DATA` seeds it on first load only); `PageResult`, the descriptor-shaped `PageController`, `PoyoPage()`, `AddPoyo()` and `MapPoyoRoutes()` arrive with ADR 0008's bundled server core; `useRouter().route` becomes the shell's reactive source of the current route (amending ADR 0005's "no router integration" posture — the resolver stays per-load, it gains subscribers); the CLI registry validator learns one field (`dynamic`), and so does the runtime (`AppRoute.dynamic`); the fixture e2e gains the descriptor seam (JSON body, `Vary` header, opt-out answering the document, protected route challenging without auth).
